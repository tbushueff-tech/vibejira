# Helper — резервный доступ к API через HostiMan

Это **PHP-прокси**, не отдельное хранилище. Он передаёт запросы с сайта Helper в существующий Cloudflare Worker. Пользователи, шифрование и зашифрованные тексты остаются общими. Путь браузер → HostiMan может работать там, где `workers.dev` заблокирован, **только если сервер HostiMan сам имеет доступ к Cloudflare**.

## Установка

1. Зарегистрируйте тариф Free на https://hostiman.ru/free-hosting и активируйте его согласно правилам провайдера. Укажите PHP 8.x и включите бесплатный HTTPS для домена (например, выданного `*.h1n.ru`).
2. Через файловый менеджер ispmanager или FTP загрузите файл [api.php](./api.php) в **корень сайта** (`public_html/api.php` или фактическую веб-директорию домена). Не загружайте этот README.
3. На рабочем компьютере коллеги откройте `https://ВАШ-ДОМЕН/api.php?route=%2Fauth%2Fme`. Нормальный ответ от Worker без авторизации: `{"authenticated":false}`, с HTTP 401. Если 502 — хостинг не может достучаться до Cloudflare, и этот вариант не решит проблему.
4. Для проверки POST из Helper нужен отдельный тест веб-приложения с правильным `Origin: https://tbushueff-tech.github.io`. Не публикуйте токены или пароли в URL и не присылайте их в чат.
5. После проверки сообщите только **публичный HTTPS-адрес** `api.php`, и мы добавим в клиенте резервное переключение. **Пока клиент не изменён:** сайт продолжает использовать только Cloudflare.

## Безопасность

- Разрешены только известные маршруты (`/auth/register`, `/auth/login`, `/auth/me`, `/auth/logout`, `/auth/password`, `/auth/crypto`, `/auth/profile` и `/`).
- `Origin` проверяется для POST-запросов; CORS разрешён только основному сайту.
- Используются HTTPS с проверкой сертификата, ограничение размера запроса и тайм-аут.
- Пароли и токены не сохраняются прокси; резервный канал **не является** автономным сервером и не работает при недоступности Cloudflare со стороны HostiMan.
- Не используйте адрес `api.php` с HTTP. Настройте принудительный HTTPS у HostiMan.

## Переключение в клиенте (после проверки)

Адрес резервного шлюза имеет вид `https://ВАШ-ДОМЕН/api.php`.
При запросах к нему вместо путей `/auth/login` и `/` нужно передавать параметр `route`:
- `/auth/me` → `api.php?route=%2Fauth%2Fme`
- `/` → `api.php?route=%2F`

После того как шлюз проверен, клиент можно научить переключаться на него только при сетевой недоступности Cloudflare (не при HTTP 401/403). Не переключать POST автоматически при неопределённом статусе отправки без защиты от дублирования регистрации и записи.
