## Постоянная библиотека кода

- На карточках временного буфера есть кнопка **☆ В библиотеку**. Она шифрует фрагмент и помещает его в личную постоянную библиотеку, не удаляя исходный текст.
- Вкладка **Библиотека** содержит поиск, ручное добавление, редактирование кода и заметок, выбор языка, копирование и удаление с подтверждением.
- У каждой записи отдельный ключ `library:<username>:<id>` в том же Cloudflare KV, без TTL. Исходный код, заголовок и заметки шифруются AES-GCM с ключом аккаунта до отправки.
- Библиотека доступна только вошедшим пользователям. Записи разных аккаунтов изолированы.
- Список передаёт только идентификаторы, зашифрованные записи читаются по частям до 2 КБ с проверкой версии, чтобы избежать зависаний больших ответов.
- Изменения и удаление используют проверку версии; данные временного буфера и его срок жизни не затрагиваются.
- Эталонная ветка `stable-v2-etalon-2026-11-10` сохранена без изменений и доступна для отката.

## Генератор демонстрационных ключей Jira

- Вкладка **Генератор ключей** повторяет формат упаковки из проекта
  [ipwnosx/Atlassian-Agent](https://github.com/ipwnosx/Atlassian-Agent):
  zlib/deflate, префикс `0D 0E 0C 0A 0F`, SHA1withDSA, DER-подпись,
  Base64, суффикс `X02` с длиной в системе счисления по основанию 31.
- Подпись генерируется **одной собственной постоянной парой DSA-ключей**,
  независимо созданной для Jira Helper, а НЕ ключом оригинального репозитория.
  Приватная часть в PKCS#8/Base64 находится в
  `v2/java/io/bushueff/jirahelper/demo/Encoder.java`, как в примере `Encoder.java`.
  Браузерная версия получает параметры DSA непосредственно из того же
  PKCS#8/Base64 в `v2/demo-private-key.js`, не храня отдельный набор `p/q/g/x`.
  `v2/demo-dsa-key.js` удалён. Тест автоматически сверяет строку PKCS#8 в
  Java `Encoder.java` и JS-модуле, чтобы они не разошлись.
  Поэтому подписи Java и JavaScript взаимно проверяются соответствующим публичным ключом.
  **Приватная часть опубликована вместе с кодом: она не секретна и не подходит
  для настоящего лицензирования или защиты данных.** Это только демонстрационные
  ключи, не подходящие для активации Jira.
- Структура свойств теперь соответствует реализации `ipwnosx/Atlassian-Agent` v1.3.1:
  `LicenseProperty` и правила `JIRASoftware`, `JIRACore`, `JIRAServiceDesk`,
  `ThirdPlugin` и остальных известных продуктов. Пользовательский Product
  задаёт namespace свойств, а не отдельное `DemoProduct`.
- Включены `keyVersion=1600708331` и **две DSA-подписи**: отсортированная
  экранированная сериализация свойств подписывается как `licenseHash`,
  после чего сжатый бинарный блок подписывается ещё раз тем же собственным ключом.
- Намеренное отличие от оригинала: **наш собственный публично доступный
  приватный ключ**. `Description` совпадает с оригиналом:
  `Unlimited license by https://zhile.io`.
  Результат не является активационной лицензией Atlassian.
- Сериализация свойств воспроизводит порядок `HashMap(32)` из Java-референса:
  исходную последовательность вставок, хеширование строк Java, цепочки корзин,
  расширение таблицы и невидимую запись `LicenseID=null` у плагинов.
  Модель рассчитана на ограниченные наборы свойств генератора; это не универсальная
  реализация всех операций Java HashMap и деревьев корзин.
- Даты покупки, создания и истечения используют локальную часовую зону браузера,
  как Java использует зону JVM. Заголовок повторяет `Date.toString()`, включая
  английские названия дней/месяцев и Java-обозначения зон (`YEKT`, `JST` и другие).
  Таблица коротких имён зон и стандартных смещений получена из Java 22;
  исторические изменения стандартного смещения и расхождения tzdata между
  браузером и JVM могут влиять на заголовок. Для современных дат проверены
  зимнее/летнее время и восемь зон. В программном API доступен необязательный
  `timeZone` с IANA-именем для воспроизводимого сравнения; форма использует местную зону.
- Внутренняя подпись по-прежнему использует отсортированные и экранированные
  свойства. Итоговые значения выводятся без экранирования, как в оригинале;
  программный API сохраняет пробелы и управляющие символы входных значений.
  Чтение такого текста стандартным Java Properties может интерпретировать
  обратные косые черты как escape-последовательности.
- Исправлена ранее существовавшая ошибка: Java Encoder.java содержал не
  соответствовавший JS DSA-ключ. Теперь его PKCS#8 получен из той же
  Jira Helper DSA-пары; тест Java ↔ JS проверяет подписи по одному public key.
- Генерация полностью локальная, введённые Server ID, email,
  организация и имя не отправляются в Cloudflare и не записываются в KV.
- **Только генерация:** Java `Encoder.java` и браузерный генератор
  `demo-keygen.js` реализуют одинаковую схему упаковки: zlib/DEFLATE,
  префикс `0D 0E 0C 0A 0F`, SHA1withDSA, Base64 и `X02` + base31.
  Используется исключительно собственный фиксированный `PRIVATE_KEY_STR`,
  согласованный с браузерной DSA-парой. Алгоритм подписи и упаковки
  сопоставлен с референсным `Encoder.java`.
- `KeyTransformer.java`, `KeyVerifier.java` и тесты трансформера удалены:
  они не нужны для создания ключа. Java Agent, патчинг проверки лицензий,
  подмена публичных ключей и сторонний JAR отсутствуют.
- Браузерная реализация воспроизводит формат и семантику свойств,
  но использует собственную DSA-пару.
  Случайные DSA-подписи и реализации DEFLATE также не требуют побайтового равенства.
  Поэтому результат **не является
  лицензией Atlassian**.
- Для тестирования совместимости: `node --test v2/demo-keygen.test.mjs` и
  `node v2/demo-java-interop.mjs` (требуется Java 17+).
- `node --test v2/demo-serialization.test.mjs` сравнивает итоговый текст и вход
  `licenseHash` с 49 сохранёнными результатами оригинальных Java-классов
  Atlassian-Agent v1.3.1, коммит `e34cc82dc4724b66b28c9a49ee92415b7bd19261`.
  Время и ID выровнены, Description взят из оригинала; вместо случайной подписи используется
  заглушка `01 02 03`. Саму DSA отдельно проверяют тесты генератора и Java interop.
  Матрица включает все известные продукты, пользовательский namespace,
  оба режима DC, переход календарного дня, летнее время и управляющие символы.

## Принципы

- Зарегистрированные пользователи имеют отдельные зашифрованные записи сроком хранения до 7 дней.
- Гостевой режим без регистрации работает локально, записи удаляются через 5 минут.
- Сессия сохраняется при обновлении страницы до выхода или истечения срока подписи.
- Облако загружается небольшими частями, защищаясь от частично переданных ответов.
- Запись использует `baseRevision` и не должна затирать более свежие изменения с другого устройства.
- Данные шифруются на клиенте; Cloudflare хранит ciphertext, а не исходный текст.
- Единственный активный API: `https://vibejira.t-bushueff.workers.dev`.
- HostiMan и экспериментальные React-ветки в продукте не используются.
